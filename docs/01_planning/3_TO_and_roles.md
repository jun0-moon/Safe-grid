# 3. 조직 및 역할 분담 (Team Organization & Roles)

## 3.1. 팀 구성 개요

본 프로젝트는 총 4인의 팀원으로 구성되며, 기획된 시스템 아키텍처를 효율적으로 구현하기 위해 <b>[백엔드/인프라], [데이터베이스/알고리즘], [프론트엔드], [데이터/QA]</b>의 4가지 핵심 파트로 역할을 세분화하여 담당합니다.

## 3.2. 세부 역할 분담

| 직무 (Role)                  | 담당 파트                            | 주요 업무 및 책임 (Responsibilities)                                                                                                                                                                                                    | 필요 기술 스택                                   |
| :--------------------------- | :----------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------- |
| **팀원 A<br>(PM & Backend)** | 프로젝트 매니징<br>백엔드 API 서버   | - 전체 프로젝트 일정(WBS) 관리 및 회의 주도<br>- 클라우드(AWS 등) 인프라 환경 구축<br>- 클라이언트와 DB를 연결하는 RESTful API 개발<br>- 우회 경로 탐색 알고리즘 백엔드 로직 구현                                                       | Node.js 또는 Spring Boot,<br>Cloud 인프라        |
| **팀원 B<br>(DBA)**          | 데이터베이스 설계<br>공간 연산 쿼리  | - 메인 DB(PostgreSQL) 및 캐시 서버(Redis) 구조 설계<br>- PostGIS를 활용한 특정 구역 밀집도 산출 공간 쿼리 작성<br>- 대규모 데이터 인입에 대비한 SQL 인덱싱 및 튜닝<br>- 백엔드 개발자와 협업하여 데이터 처리 파이프라인 최적화          | PostgreSQL, PostGIS,<br>Redis, SQL 튜닝          |
| **팀원 C<br>(Frontend)**     | 모바일 웹 UI/UX<br>지도 API 연동     | - 사용자 접근성을 고려한 모바일 반응형 웹 UI/UX 구현<br>- 브라우저 Geolocation API를 활용한 사용자 위치 수집 로직<br>- 카카오맵/네이버 지도 API 연동 및 폴리곤(구역) 렌더링<br>- 서버로부터 받은 밀집도 데이터를 바탕으로 히트맵 시각화 | HTML/CSS/JS,<br>React.js 또는 Vue.js,<br>Map API |
| **팀원 D<br>(Data & QA)**    | 더미 데이터 생성<br>성능 테스트 (QA) | - 대규모 군중 밀집 상황 가정을 위한 GPS 더미 데이터 생성 스크립트 작성 (초당 수백 건 발생)<br>- JMeter를 활용한 서버 및 DB 트래픽 부하 테스트(스트레스 테스트) 수행<br>- 병목 지점 리포팅 및 전체 시스템 버그 수정(QA)                  | Python,<br>JMeter, QA 툴                         |

> **? 참고:** 면접 등에서 데이터베이스 역량을 강조하고 싶다면 **'팀원 B (DBA)'** 역할을 맡아 시스템의 성능 병목을 해결하는 핵심 역할을 수행하는 것을 권장합니다.

## 3.3. 협업 규칙 및 커뮤니케이션 (Collaboration Rules)

- **버전 관리 (Git Flow):** \* 메인 브랜치(`main` 또는 `master`)에는 직접 Push하지 않습니다.
  - 각자 맡은 기능은 `feature/기능명` 브랜치를 생성하여 작업한 후, Pull Request(PR)를 통해 팀원들의 코드 리뷰를 거쳐 병합(Merge)합니다.
- **일정 및 태스크 관리:** \* Github Projects(또는 Notion 칸반 보드)를 활용하여 `To-Do`, `In Progress`, `Done` 상태로 각자의 업무를 시각화하고 진척도를 공유합니다.
- **커뮤니케이션 채널:** \* **Discord:** 실시간 회의, 화면 공유를 통한 짝 코딩(Pair Programming), 긴급 이슈 공유.
  - **Notion:** 회의록 작성, API 명세서 및 DB 테이블 정의서(ERD) 등 산출물 통합 관리.
